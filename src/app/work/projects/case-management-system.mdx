## Overview

Case information in many organizations is scattered across spreadsheets, inbox threads, and personal notes. This project centralizes case records into a searchable system with consistent master data (courts, judges, subject matters, etc.), enabling teams to track hearings, manage documentation, and answer operational questions quickly.

### What it does

- **Case lifecycle tracking**: create/update cases with rich metadata (status, court/location, subject, contacts, revenue, tasks)
- **Hearing visibility**: dashboard summary counts + next-hearing date highlights
- **Fast retrieval**: filtering by status and hearing-date ranges
- **Master data modules**: courts, locations, benches, judges, departments, designations, statuses, subject matters
- **Documents**: upload a main case file + per-remark attachments; download/open stored files
- **User permissions**: `read-only` vs `read-write` access enforced in the UI

## Architecture

- **Frontend**: React (Vite) app using React Router, Axios, Tailwind + UI primitives
- **Backend**: Express REST API with Mongoose models and Multer for multipart uploads
- **Storage**: MongoDB for structured data; file uploads stored on disk (served from `backend/uploads/`)

## Engineering Highlights

- **Normalized data model**: separated master data from cases to keep inputs consistent and reduce rework.
- **Intranet-friendly deployment**: designed for VM/local-network hosting (reverse proxy → static UI + API → MongoDB).
- **Permission-aware UX**: route protection + write-guarded actions to prevent accidental edits while keeping the app usable for read-only stakeholders.
- **Demo/dev readiness**: added a seed script to generate realistic dataset for verification and demos.
