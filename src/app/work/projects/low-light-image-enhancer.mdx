## AI Image Enhancement Studio

**One-line summary:**  
Built a lightweight image restoration web app that colorizes grayscale photos and improves low-light images with predictable runtime—useful for real-world restoration workflows where “just increase exposure” fails.

### Problem

Two common restoration tasks are deceptively hard in production:

- **Low-light enhancement**: boosting brightness often amplifies noise, clips highlights, and shifts colors because the signal-to-noise ratio collapses in dark regions.
- **Colorization**: grayscale-to-color is fundamentally ambiguous—multiple valid colors can match the same luminance—so naive tinting or histogram tricks produce flat, inconsistent results.

### Initial Approach & Failure

- **Zero-DCE (low-light enhancement prototype)**
- **Why it failed**: improvements plateaued on real images, generalized poorly outside the LOL-style distribution, and produced noise amplification / instability in extremely dark regions.
- **What I learned**: for an end-user app, stability and predictable behavior matter more than a “clever” method that needs careful tuning to avoid artifacts.

### Final Solution

- **Model architecture chosen**: a MIRNet-inspired enhancement strategy, shipped as a fast deterministic pipeline (CLAHE + denoise + gamma + mild sharpening) with an optional deep-model hook reserved for later.
- **Why this model was better suited**: it’s stable across diverse inputs and is deployable on CPU without training-time dependencies.
- **Data handling and preprocessing approach**: input validation (file type + size), defensive image decoding (PIL → NumPy), and color-space transforms (LAB/HSV) to adjust luminance while protecting chroma.

### Key Engineering Decisions

- **Model choice reasoning**: used a pre-trained OpenCV-DNN Caffe colorization model (Zhang et al., ECCV 2016) to get consistent outputs without owning training.
- **Inference vs training trade-offs**: the repo is intentionally inference-first—no training pipeline shipped—so the system stays reproducible and easy to deploy.
- **Why this model instead of alternatives**: Zero-DCE introduced instability and domain-shift issues; the MIRNet-style pipeline provided a better reliability/latency trade-off for a web workflow.
- **Deployment-related decisions**: packaged both pipelines behind a single Flask app with a unified `/process` endpoint, health checks, and predictable error responses.

### Results & Observations

- Qualitative improvements: better midtone visibility and local contrast on underexposed images; plausible colorization on common portraits/objects.
- Quantitative metrics: not included in the repository (no PSNR/SSIM/LPIPS harness shipped).
- Limitations: severe underexposure can still reveal grain/noise after enhancement; colorization can pick implausible hues on rare objects, low-texture regions, or domain-shifted imagery.

### Constraints & Challenges

- Underexposed regions have low SNR, so any luminance lift risks noise amplification.
- Domain shift (“in-the-wild” images vs curated datasets) quickly exposes brittle models.
- Ambiguity in colorization means outputs are plausible guesses, not ground truth.
- Deployment practicality: CPU-friendly inference, bounded uploads, and predictable error handling were prioritized over heavy training pipelines.
